# Handoff: extend the Iowa bourbon price panel back to 2003

Repository `junishka/bourbonresearch`, branch `claude/bourbon-price-data-sources-ejx9qy`, working directory `pipeline/`. Read `README.md` and `../price-data-sources.md` first.

## Context

The project links TTB COLA label records (bourbon, 2000 onward) to a longitudinal retail price series. Iowa is a control state and its posted wholesale-to-retailer price is the series. For 2012 to April 2026 the panel is already built from the state's transaction data (`data/item_master.csv`, 1,251 items; `data/item_month.csv`, 22,594 item by month rows; 750 ml bourbon only). Before 2012 there is no transaction data, but the Iowa Alcoholic Beverages Division published the Iowa Liquor Quarterly, a PDF containing the monthly wholesale price list booklet, archived at publications.iowa.gov for 2003 to 2013. Item numbers should be the same series as in the 2012 data, so the 2003 to 2011 prices can be appended to the existing panel.

## Goal

Produce `data/item_month_2003_2011.csv` with the posted price per bourbon 750 ml item per month, and `data/item_master_2003_2011.csv` listing those items, both in the same column style as the 2012 files. Then `data/item_month_2003_2026.csv` as the union with the existing panel. Bottles sold and sale dollars do not exist before 2012; leave those columns empty for the early years.

## Steps

1. Download. `python3 fetch_iowa_quarterly.py --outdir data/quarterly_pdfs` (standard library only). It scrapes the subject listing at https://publications.iowa.gov/view/subjects/BBA.html for records titled "Iowa Liquor Quarterly" and saves `iowa_liquor_quarterly_YYYY_MM.pdf`. Known record ids if the scrape fails: 2789 to 2797 cover 2003 to 2005, 16933 to 16951 cover 2010 to 2013; the 2006 to 2009 ids are on the listing page. Get everything from 2003 through 2013. The 2012 and 2013 issues are for validation.

2. Inspect. `python3 inspect_quarterly.py data/quarterly_pdfs/iowa_liquor_quarterly_2004_02.pdf --pages 0-3` and the same for a 2008 and a 2012 issue. It reports text versus scanned, page count, and which pages look like price lists. Work out: the row layout (item code, description, size, pack, price columns, and whether both a state cost and a retail price appear), how categories are marked (section headers such as STRAIGHT BOURBON WHISKIES, or code ranges), whether each issue holds one list or three monthly lists, and whether some issues hold only changes and new items rather than the full list. Write what you find at the top of the parser as a comment.

3. Parse. Write `parse_quarterly.py` that takes the PDF directory and emits one row per item per month: `item_number, month, state_bottle_retail, state_bottle_cost (if present), item_description, bottle_volume_ml, pack, category_name, source_issue`. Keep bourbon categories and 750 ml only, but parse everything first and filter at the end so the filter can be checked. If an issue lists only changes, carry the previous full list forward and apply the changes. Handle one layout per era; expect two or three across the decade. For two-column pages use pdfplumber `extract_words` with x positions or crop each column, not `extract_text`.

4. Validate against known data. Parse the four 2012 issues and compare with `data/item_month.csv` for the same months. Expected: item numbers overlap heavily, and the parsed price equals `state_bottle_retail_median` exactly for most items (the transaction price is the posted price). Report the share of items matched and the share of prices equal. Anchors: item 19066 JIM BEAM 750 ml was 13.41 in 2012-01; item 17956 EVAN WILLIAMS STR BOURBON and 22156 BUFFALO TRACE are also continuous. If the 2012 reconciliation is below about 95 percent on price equality, the parser has a problem; fix it before going backward.

5. Build outputs. Write the three CSVs listed under Goal. For `item_master_2003_2011.csv` use the most frequent description per item, first and last month seen, and number of months. Commit the parser and the CSVs. Do not commit the PDFs unless they are small; add `data/quarterly_pdfs/` to `.gitignore` otherwise.

6. Report. Number of issues parsed, layouts found, months covered, items per year, the 2012 reconciliation rates, and any years with gaps.

## Pitfalls

- Scanned issues need OCR (`pdf2image` plus `pytesseract`). Digits come out wrong often. Validate every parsed row: item code is 4 to 6 digits, price matches `\d+\.\d\d`, size is a known bottle size. Drop rows that fail and count them.
- Item numbers may carry leading zeros in the booklets. Normalize to the plain integer string used in `data/item_master.csv`.
- Sizes may print as 750ML, .750, 750 or 75 CL. Normalize to millilitres.
- Prices may change mid-quarter. If the issue is quarterly but contains monthly lists, keep the monthly granularity; if it is one list per quarter, set month to each of the three months and note that in the report.
- A price list may include the retailer price and the state's cost. The panel column `state_bottle_retail` is the price the store pays the state, not the shelf price.

## Environment

Python 3.10 or newer with `pandas`, `pdfplumber`, `rapidfuzz`, `duckdb`. OCR only if needed: `pdf2image`, `pytesseract`, and the tesseract binary.
